## Phase 2: v1.2 — Shareability (Weeks 1-2)

Goal: Make crash reports readable without the CLI tool.

### 2.1 HTML Crash Report Export

`safedump view --html` generates a self-contained HTML report from a .safedump.json file. No server needed. Opens in any browser.

**Files:**
- Create: `src/safedump/_html_render.py` (HTML template + render function)
- Modify: `src/safedump/_cli.py` (add `--html` flag to `view` subcommand)
- Create: `tests/test_html_render.py`

**Requirements:**
- Self-contained HTML (no external CSS/JS)
- Dark theme by default
- Expandable frame sections with syntax-highlighted code
- Variable values with type badges
- Collapsible environment/thread info
- Copy-to-clipboard for JSON raw report
- Print-friendly CSS

**Edge cases:**
- Very large reports (100+ frames) — lazy render only visible frames
- Unicode special characters in variable values
- Missing optional fields in older report versions
- HTML injection in exception messages (escape all output)

### 2.2 Local Web Server

`safedump serve` starts a local web UI for browsing all crash reports.

**Files:**
- Create: `src/safedump/_server.py`
- Modify: `src/safedump/_cli.py` (add `serve` subcommand)
- Create: `tests/test_server.py`

**Requirements:**
- List all reports sorted by timestamp
- Click to view HTML report
- Search/filter by exception type, date, message
- Delete reports from UI
- Only listens on `127.0.0.1` (never expose to network)
- `--port` and `--host` flags for customization
- Auto-open browser on start

**Edge cases:**
- No reports exist (empty state)
- Port already in use (auto-increment or fail gracefully)
- Concurrent access while report is being written
- Broken symlinks or corrupted report files

### 2.3 Report Filtering in CLI

`safedump list --type KeyError --since 7d --limit 10`

**Files:**
- Modify: `src/safedump/_cli.py` (add filter options to `list` subcommand)
- Modify: `src/safedump/_storage.py` (list/filter/query helpers)

**Requirements:**
- Filter by exception type
- Filter by date range
- Filter by search text in message
- Sort by time, type, or message
- Limit results

### 2.4 Report Statistics

`safedump stats` shows aggregate data.

**Files:**
- Modify: `src/safedump/_cli.py`
- Create: `src/safedump/_stats.py`
- Create: `tests/test_stats.py`

**Requirements:**
- Total crash count
- Most common exception types
- Crashes per day chart (simple ASCII bar chart)
- Average response time improvement
- Data about which files crash most

## Phase 3: v1.3 — Smarter Detection (Weeks 3-4)

### 3.1 Entropy-Based Secret Detection

Currently secrets are detected by variable name patterns (denylist). Add opt-in entropy detection that finds high-entropy strings that look like API keys, tokens, or passwords regardless of variable name.

**Files:**
- Create: `src/safedump/_entropy.py`
- Modify: `src/safedump/_config.py` (add `entropy_detection: bool` option)
- Modify: `src/safedump/_sanitize.py` (call entropy check during sanitization)
- Create: `tests/test_entropy.py`

**Requirements:**
- Shannon entropy calculation per string
- Entropy threshold configurable (default 4.5 bits/char)
- Requires explicit opt-in (`configure(entropy_detection=True)`)
- Applied AFTER denylist matching (entropy is slower)
- Skip strings shorter than 20 characters
- Skip strings that match common low-entropy patterns (dates, emails, URLs)

**Edge cases:**
- Very long strings (truncate before analysis)
- Unicode text (normalize to NFC first)
- Empty strings
- Binary strings
- Strings that look high-entropy but are actually encoded (base64, hex)
- Performance impact on crash capture time

### 3.2 Enhanced before_capture Hook

The current `before_capture` hook is a single callback. Add support for:
- Multiple hooks (chain pattern)
- Async hooks
- Hook priority ordering

**Files:**
- Modify: `src/safedump/_config.py`
- Modify: `src/safedump/_capture.py` (chain execution)
- Modify: `tests/test_capture.py`

### 3.3 Crash Report Deduplication

When the same crash happens repeatedly, group them instead of writing duplicate reports.

**Files:**
- Create: `src/safedump/_dedup.py`
- Modify: `src/safedump/_storage.py` (grouped save)
- Create: `tests/test_dedup.py`

**Requirements:**
- Fingerprint based on exception type + message + crash site (file+line)
- Subsequent same-fingerprint crashes increment a counter instead of writing a new file
- CLI shows count per fingerprint
- Optional with `configure(dedup=True)` (default off for now)

### 3.4 Crash Report Email/Slack/Webhook Notifications

Optional notification when a crash is captured.

**Files:**
- Create: `src/safedump/_notify.py`
- Modify: `src/safedump/_config.py`
- Create: `tests/test_notify.py`

**Requirements:**
- SMTP email notification
- Slack webhook
- Custom webhook URL
- Configurable in `configure()` or via JSON config file
- Rate-limited (max 1 notification per 5 minutes per exception type)
- Does NOT block crash capture

## Phase 4: v2.0 — Plugin Ecosystem (Weeks 5-8)

### 4.1 Stable Plugin API

Design and freeze a plugin system that allows third-party packages to extend Safedump.

**Files:**
- Create: `src/safedump/_plugin_api.py`
- Create: `docs/plugin-development.md`
- Modify: `src/safedump/__init__.py`
- Create: `tests/test_plugin_api.py`

**Plugin capability categories:**

1. **Serializers** (already exists via `register_serializer` - formalize)
2. **Formatters** (HTML, Markdown, PDF, etc.)
3. **Notifiers** (email, Slack, SMS, etc.)
4. **Sanitizers** (custom redaction logic)
5. **Analyzers** (crash patterns, stats aggregation)
6. **Storage backends** (S3, local alternative paths, etc.)

**Design requirements:**
- Entry-point based discovery (`safedump.plugins` entry point group)
- Versioned plugin API (semver)
- Manifest with required fields (name, version, capabilities)
- Sandbox execution (plugin errors never crash the host)
- Documentation for plugin authors

### 4.2 First-Party Plugin: Sentry Integration

A plugin that forwards crash reports to Sentry when Sentry SDK is installed.

**Files:**
- Create: `safedump-plugins/sentry/`
- Integration with register_serializer pattern

### 4.3 Performance Benchmarks

Create a benchmarks page comparing Safedump against:
- Stdlib traceback
- rich.traceback
- stackprinter
- Sentry SDK

**Files:**
- Create: `docs/benchmarks.md`
- Create: `scripts/benchmarks.py`

**Metrics:**
- Crash capture overhead (microseconds)
- Memory usage at capture time
- Report size (bytes)
- File write time

### 4.4 Comprehensive Documentation Site

MkDocs / GitHub Pages site.

**Files:**
- Create: `docs/` infrastructure (mkdocs.yml)
- API reference
- Tutorials
- FAQ
- Plugin development guide
- Release notes

### 4.5 API Stability & Deprecation Policy

Formalize the deprecation process:
- Deprecation warning in 1 minor version before removal
- Migration guide for breaking changes
- `__all__` is the only public API surface
- Everything else is private

## Risks & Mitigations

| Risk | Impact | Likelihood | Mitigation |
|------|--------|------------|------------|
| Plugin API design too restrictive | Need to break API in v2.1 | Medium | Start with 3 reference plugin implementations before freezing API |
| HTML renderer complexity | Delays v1.2 | Low | Use minimal template, iterate based on feedback |
| Entropy detection false positives | Users disable feature | Medium | Conservative thresholds. Warnings in report. User-adjustable. |
| Scope creep on v1.2 | Never ships | High | Cut features ruthlessly. `serve` can move to v1.3 if needed. |
