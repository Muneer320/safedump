## Part II: v1.2 — Shareability (2 weeks)

Theme: Making crash reports useful outside the terminal.

---

### Feature 1: HTML Crash Report Export

**What:** `safedump view --html` generates a self-contained .html file. No server required. Opens in any browser. One file can be attached to bug reports.

**Why:** JSON crash reports aren't readable by non-developers. Terminal output cannot be attached to GitHub issues or emailed. HTML solves both.

**Why NOT:** The upcoming `safedump serve` also provides a web view. Are both needed?

**Decision:** YES. Export and serve serve different needs. Export = one-shot sharing (attach to issue). Serve = browsing history locally. Both are valuable.

**Approach research:**
1. Jinja2 template (heavy dep, must be optional like Rich)
2. f-string template (zero deps, stdlib, sufficient)
3. dominate/lxml (overly complex)

**Choice:** f-string template. Zero dependencies. If template exceeds 200 lines and becomes unmaintainable, move to Jinja2.

**Requirements:** Dark theme, expandable frames, type badges, copy-JSON button, print CSS. --output flag for custom path.

**Edge cases:** 100+ frames (collapsible details), Unicode/html injection (escape all values), missing optional fields (graceful N/A), binary locals (skip with warning), old schema versions (error message).

**Files:** CREATE `src/safedump/_html_render.py` (~120 lines), MODIFY `_cli.py` (+30), MODIFY `pyproject.toml` for optional [html] extra, CREATE `tests/test_html_render.py` (~80 lines).

---

### Feature 2: Local Web Server

**What:** `safedump serve` starts a local web server with an HTML dashboard.

**Why:** CLI browsing requires back-and-forth (list → copy ID → view → list). A web UI shows all reports at once.

**Security:** Bind to 127.0.0.1 ONLY by default. Warn on non-localhost binds.

**Architecture:** Two endpoints: static HTML client and JSON API.
- GET / → index.html (the app)
- GET /api/reports → JSON list
- GET /api/reports/<hash> → HTML of one report
- GET /api/reports/<hash>/raw → raw JSON
- DELETE /api/reports/<hash> → delete

**Frontend:** Single HTML file with embedded CSS+JS. Zero build step. Vanilla JS fetch().

**Implementation:** http.server (stdlib), ThreadingMixIn for concurrent requests, custom RequestHandler. Background thread for auto-open browser. Graceful shutdown.

**Edge cases:** Port in use (try +1 to +5), empty state, concurrent writes, headless servers.

**Files:** CREATE `src/safedump/_server.py` (~200 lines), MODIFY `_cli.py` (+20), CREATE `tests/test_server.py` (~120 lines).

### Feature 3: CLI Report Filtering

**What:** `safedump list --type KeyError --since 7d --limit 10 --sort time --search "timeout"`

**Why:** As users accumulate reports, unfiltered listing is noise. Most common need: "show KeyErrors from this week."

**Decision:** YES. Small change (~90 lines total). Future-proof API design.

**Filter API:** --type (substring), --since/--until (ISO or human: "7d", "24h"), --limit, --sort (time/type/message), --search (message/type/filename).

**Files:** MODIFY `_storage.py` (+60 lines), MODIFY `_cli.py` (+30 lines), MODIFY `tests/test_cli.py` (+50 lines).

## Part III: v1.3 — Smarter Detection (2-3 weeks)

---

### Feature 5: Entropy-Based Secret Detection

**What:** Opt-in detection of high-entropy strings that the denylist misses.

**Research on entropy detection:**
- Shannon entropy H(x) = -ΣP(x)·log₂P(x). High entropy (~5-6 bits/char) = likely secret.
- Published papers report 30-60% FP rates for pure entropy detection (GitGuardian, IEEE S&P 2023).
- Combined with context analysis (variable name, path), FP drops to ~15%.
- 4.5 bits/char is industry standard threshold.

**False positive mitigations:** Skip strings under 20 chars, skip common patterns (dates, emails, URLs, paths, IPs), run AFTER denylist, flag-only below privacy_tier 3.

**Decision:** YES but STRICTLY OPT-IN. Default: `entropy_detection=False`. User explicitly enables.

**Files:** CREATE `_entropy.py` (~80 lines), MODIFY `_config.py`, MODIFY `_sanitize.py`, CREATE `tests/test_entropy.py` (~100 lines).

---

### Feature 6: Crash Report Deduplication

**What:** Same crash (type + message + location) grouped under one fingerprint with counter.

**Edge case:** Changes file format, breaks naive directory parsers.

**Decision:** OPT-IN (`configure(dedup=True)`). Fingerprint = SHA256 of type|message|file|line.

**Files:** MODIFY `_config.py`, MODIFY `_storage.py` (+80 lines), MODIFY `_types.py`, CREATE `tests/test_dedup.py`.

---

### Feature 7: Crash Notification Hooks

**What:** Optional SMTP email and HTTP webhook notifications after capture.

**Constraints:** Run AFTER file write (never block capture), 5s timeout, best-effort, rate-limited (1 per 60s per type). Credentials in memory config.

**Built-in:** SMTP via smtplib (stdlib), webhook via urllib.request (stdlib).

**Files:** CREATE `_notify.py` (~150 lines), MODIFY `_config.py`, MODIFY `_capture.py` (+15 lines), CREATE `tests/test_notify.py`.

## Part IV: v2.0 — Plugin Ecosystem (4-6 weeks)

---

### Feature 8: Stable Plugin API

**Approach research:**
- importlib.metadata entry points: stdlib, zero deps. Used by pytest/flake8/mypy/ruff. Winner.
- pkg_resources: deprecated. Skip.
- pluggy: one dep, 80KB. Overkill for Safedump's needs.

**Choice:** importlib.metadata.entry_points(). Zero deps, stdlib, battle-tested.

**Categories:** Serializers, Formatters, Notifiers, Sanitizers (4 groups).

**Why NOT yet:** No real plugin authors exist. register_serializer already covers the main case.

**Decision:** v2.0 only after 3 reference plugins validate the API.

**Files:** CREATE `_plugin_api.py`, MODIFY `__init__.py`, CREATE `docs/plugin-development.md`, CREATE `tests/test_plugin_api.py`.
